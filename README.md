# パエリア 紙整理券管理

紙の整理券を配布・回収しながら、スタッフが1台の端末で、連番の配布はボタンひとつ、提供は番号入力で管理するWebアプリです。顧客情報、ログイン、QRコード、クラウド同期はありません。

## 起動方法

公開URL： **https://hiromu-0219.github.io/paella-sys/**

公開版はこのURLをブラウザで開くだけで利用できます。ローカルサーバーは不要です。イベントと整理券のデータはアクセスした端末のブラウザ内に保存され、GitHubには送信されません。ローカル版と公開版の保存領域は別のため、ローカル版のデータは自動では移りません。

GitHubリポジトリ： https://github.com/Hiromu-0219/paella-sys

`main` にpushするとGitHub Actionsがテスト・ビルドを実行し、成功した場合にGitHub Pagesを更新します。配信設定は `.github/workflows/pages.yml` にあります。

### PC内で起動する場合

Node.js 22以上とnpmを使用します。このフォルダーで次を実行してください。

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

ブラウザで **http://127.0.0.1:5173** を開きます。起動したターミナルは使用中に閉じないでください。停止はCtrl+Cです。端末を再起動したら、このフォルダーで `npm.cmd start` を実行し、同じブラウザ・同じURLで開いてください。毎回のビルドやイベント作成は不要です。

開発中は `npm.cmd run dev` を使用します。開発と本番プレビューは同じURLに固定しています。ポートが使用中の場合は自動的に別ポートへ変更せず停止します。`dist/index.html` を直接開く方法には対応していません。

## 使い方

1. 初回のみ、イベント名と整理券発行枚数（1〜10,000）を入力します。1番から全て未配布として生成します。
2. 「今回配布する番号」と紙の番号を確認し、「No.001 を配布する」のようなボタンを押します。番号入力は不要です。
3. 配布後は次の未配布番号に自動で進みます。配布済み・提供済み・無効の番号は飛ばし、未配布がなくなるとボタンは無効になります。例外的に番号を指定したい場合は「番号を指定して配布」に切り替え、番号入力＋配布ボタンまたはEnterで確定します。「連番で配布に戻る」で通常操作に戻れます。
4. パエリアを渡したら上部の「提供」タブに切り替え、「提供済みにする」に番号を入力し、提供完了またはEnterで確定します。「配布」タブに戻ると連番配布を続けられます。配布と提供はそれぞれ独立した画面です。
5. 「整理券一覧」で状態を絞り込み、番号を検索できます。番号は完全一致検索です（043と43は同じ番号）。整理券を選ぶと日時と可能な操作を表示します。
6. 誤操作の訂正・無効化・無効解除は詳細画面から行います。必ず確認ダイアログで確定してください。キャンセル・Esc・閉じるでは変更しません。
7. 「操作履歴」で日時、番号、操作、変更前後の状態を確認します。新しい順に50件ずつ表示します。
8. 終了後に「バックアップ保存」でイベント、整理券、全履歴をJSONファイルとして保存できます。
9. 「新しいイベントを開始」は現在のイベント名を正確に再入力し、「保存して新しく開始」を押すと、現在のイベントを整理券・履歴ごと保存して初期設定に戻ります。

「保存したイベント」は管理画面と初期設定画面から開けます。過去イベントを選び「このイベントを開く」で続きから操作できます。現在開いているイベントがある場合は、それも保存して切り替えます。キャンセルでは変更しません。イベント名が同じでも内部IDで区別します。

## 集計の定義

| 表示       | 定義                                         |
| ---------- | -------------------------------------------- |
| 発行総数   | 生成した整理券枚数                           |
| 配布済み数 | ISSUED＋SERVED（無効を除く現在の有効配布数） |
| 提供済み   | SERVED                                       |
| 待機中     | ISSUED                                       |
| 未配布     | UNISSUED                                     |
| 無効       | INVALID                                      |

未配布＋待機中＋提供済み＋無効＝発行総数です。「配布済み数」は過去の配布操作の累計ではありません。

## 保存方法と運用上の注意

- **IndexedDB** の `paella-tickets-v1` データベース、`data` ストア、`current` キーに現在のイベント、`event:<イベントID>` キーに保存済みイベントを保持します。以前の保存データもそのまま読み込めます。ページ更新・ブラウザ終了・端末再起動で保持されます。
- 整理券変更と履歴追加を1つのreadwriteトランザクションで確定します。読み込みから書き込みまでトランザクション内で処理するため、同一ブラウザの複数タブで二重操作しても一方だけ成功します。保存完了前に成功表示しません。保存に失敗した操作は確定しません。
- `durability: strict` を指定し、イベント作成時にはブラウザへ永続ストレージ保護をリクエストします。許可の可否はブラウザが決めます。画面上部で結果を確認できます。
- 同一ブラウザのタブ間はBroadcastChannelで表示更新します。フォーカス復帰時も読み直します。複数端末間の同期はありません。
- **通常モードの同じブラウザ・同じプロファイル・同じURLを使ってください。** `localhost` と `127.0.0.1`、異なるポート、HTTPとHTTPSは別保存領域です。
- プライベートモード、ブラウザのサイトデータ削除、端末故障、ストレージ不足による消去から完全には保護できません。定期的にバックアップを保存してください。JSONは外部保管用で、v1にファイルの取り込み画面はありません。必要時に開発者が復旧に利用できます。
- JSONに個人情報はありません。番号・日時・イベント名・履歴が含まれます。
- 新規イベントへの移行・保存済みイベントへの切り替えは、保存と切り替えを同一トランザクションで確定します。画面にイベント削除機能はありません。バックアップは現在開いているイベントが対象です。
- 読み込み失敗時は初期設定画面へ勝手に戻さず、データを残したままエラーを表示します。

## データモデルと状態遷移

`EventData`: id、name、ticketCount、createdAt。`Ticket`: number、status、issuedAt、servedAt、invalidatedAt、previousStatus。`OperationLog`: id、ticketNumber、action、previousStatus、newStatus、createdAt。保存データにはschemaVersionとrevisionも保持します。

```text
未配布 --配布--> 配布済み --提供--> 提供済み
未配布 <--訂正-- 配布済み <--訂正-- 提供済み
各有効状態 --無効化--> 無効 --無効解除--> 無効化前の状態
```

配布済みから未配布へ戻すと配布日時を消し、提供済みから配布済みへ戻すと提供日時を消します。元の操作は履歴に残ります。無効化は元の状態と日時を保存し、解除すると元に戻します。不正な遷移はUIに加えて保存処理から呼び出すドメイン関数でも拒否します。確認中に別タブで状態が変わった場合やイベントが変更された場合も拒否します。

## 構成

```text
src/
  domain.ts       データ型、入力検証、状態遷移、集計
  storage.ts      IndexedDBの読み込み・原子的更新
  main.tsx        初期設定、管理、一覧、詳細、履歴、確認画面
  style.css       PC・タブレット・スマートフォン向けスタイル
tests/
  domain.test.ts  状態遷移・入力・集計のテスト
  storage.test.ts 保存・同時操作・初期化のテスト
  e2e/app.spec.ts 実ブラウザでの操作・再起動・モバイル表示
```

React 19 / TypeScript / Vite。外部サーバーやデータベースサービスは不要です。依存関係のインストール後は、PC内のローカルサーバーでインターネット接続なしに利用できます。

## テスト

```powershell
npm.cmd test
npm.cmd run test:e2e
npm.cmd run build
```

E2Eはインストール済みのMicrosoft Edgeを使います。`playwright.config.ts` のchannelを変更すればChromeでも実行できます。E2Eは分離したテスト用プロファイルを使用し、普段のブラウザデータを変更しません。保存の検証には、実ブラウザプロセスを終了して同じテストプロファイルで起動し直すケースを含みます。OS自体を再起動するテストは自動化していません。

## 現時点の制限と今後の拡張

実装時の検証結果：状態遷移・保存の54テスト、EdgeでのE2E 6テスト、本番ビルドが成功しました。E2Eでは二重配布防止、確認キャンセル、訂正・無効解除、イベント保存・切り替え、ページ更新、ブラウザプロセスの再起動後の復元、PC幅1440px／スマートフォン幅390pxでの表示を確認しています。

- 1端末で複数のイベントを保存し、1つずつ開いて管理できます。複数端末同期はありません。
- スマートフォン・タブレットでも操作できるレスポンシブUIです。ただしローカル起動URLは起動したPC専用です。別端末で運用するには、安定した同一オリジンのHTTPS静的ホスティングなどを別途用意してください。配信する端末を変えても保存データは移動しません。
- オフライン用Service Worker／PWAは未実装です。ローカルPC運用では起動中のサーバーが必要です。
- 操作履歴は削除・編集しません。全データをまとめて保存するシンプルな構成のため、非常に大量の履歴を扱う運用にはストアの分割が拡張候補です。
- 次の拡張候補：検証付きバックアップ取り込み、PWA。ログインや顧客情報は不要なまま拡張できます。
